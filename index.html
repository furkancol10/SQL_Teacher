CREATE TABLE Syntax

Define a table with columns, data types, and constraints. Use NOT NULL for required fields, and REFERENCES for foreign key relationships.

SQL
CREATE TABLE dbo.customer (
  CustomerID        int          NOT NULL PRIMARY KEY,
  CustomerFirstName varchar(50)  NOT NULL,
  CustomerLastName  varchar(50)  NOT NULL,
  CustomerAddress   varchar(50)  NOT NULL,
  CustomerSuburb    varchar(50)  NULL,
  CustomerCity      varchar(50)  NOT NULL,
  CustomerPostCode  char(4)      NULL,
  CustomerPhoneNumber char(12)   NULL
);

CREATE TABLE dbo.sale (
  SaleID       tinyint    NOT NULL PRIMARY KEY,
  CustomerID   int        NOT NULL REFERENCES customer(CustomerID),
  InventoryID  tinyint    NOT NULL REFERENCES Inventory(InventoryID),
  EmployeeID   tinyint    NOT NULL REFERENCES Employee(EmployeeID),
  SaleDate     date       NOT NULL,
  SaleQuantity int        NOT NULL,
  SaleUnitPrice smallmoney NOT NULL
);
💡 Use SELECT * FROM information_schema.tables to see all tables in your database.
🔍 Lesson 02

Querying Basics

SELECT is the bread and butter of SQL. Learn how to retrieve data, limit results, sort output, and remove duplicates.

🔝

TOP — Limiting Results

Retrieve only the first N rows, or a percentage of the total results.

SQL
-- Show only the first 2 rows
SELECT TOP 2 * FROM customer;

-- Show the first 40% of rows
SELECT TOP 40 PERCENT * FROM customer;
📊

ORDER BY — Sorting Results

Sort results in ascending (default) or descending order. You can sort by column name or column position number.

SQL
-- Sort by last name descending
SELECT CustomerFirstName, CustomerLastName
FROM customer
ORDER BY CustomerLastName DESC;

-- Sort by column position (no need to type column name)
SELECT CustomerFirstName, CustomerLastName
FROM customer
ORDER BY 4, 2, 3 DESC;
✨

DISTINCT & INTO

Use DISTINCT to return only unique values. Use INTO to save query results into a new table.

SQL
-- Only show unique last names
SELECT DISTINCT CustomerLastName FROM customer
ORDER BY CustomerLastName;

-- Save result into a new table
SELECT DISTINCT CustomerLastName INTO temp
FROM customer
ORDER BY CustomerLastName;
🔎 Lesson 03

Filtering Data

The WHERE clause lets you filter rows based on conditions. SQL provides powerful operators like LIKE, IN, BETWEEN, and IS NULL.

🔤

LIKE — Pattern Matching

Search for patterns in text columns. Use _ for a single character and % for zero or more characters.

SQL
-- _ matches exactly one character
-- % matches zero, one, or multiple characters
SELECT * FROM customer
WHERE CustomerLastName LIKE '_r%';
💡 '_r%' finds names where the 2nd character is 'r' — e.g., Brown, Cross, Arnold.
📋

IN — Match Multiple Values

Check if a value exists in a list — cleaner than chaining multiple OR conditions.

SQL
SELECT * FROM customer
WHERE CustomerLastName IN ('Brown', 'Michael', 'Jim');
↔️

BETWEEN, NULL Checks & Comparison

Use BETWEEN for ranges, IS NULL / IS NOT NULL for null checks, and <> for "not equal".

SQL
-- Range filter
SELECT * FROM sale
WHERE SaleUnitPrice BETWEEN 5 AND 10;

-- Check for NULL values
SELECT * FROM customer
WHERE CustomerLastName IS NULL;

-- Not equal
SELECT * FROM customer
WHERE CustomerLastName <> 'Brown';

-- Comparison with OR
SELECT * FROM customer
WHERE CustomerLastName > 'Brown' OR CustomerLastName > 'Cross';
📈 Lesson 04

Aggregate Functions

Aggregate functions perform calculations across sets of rows and return a single value. They're essential for reporting, analytics, and data summarization.

FunctionDescriptionExample
COUNT(*)Number of rowsSELECT COUNT(*) FROM customer
SUM(col)Total of a numeric columnSELECT SUM(SaleQuantity) FROM sale
MAX(col)Largest valueSELECT MAX(Salary) FROM EmployeeSalary
MIN(col)Smallest valueSELECT MIN(Salary) FROM EmployeeSalary
AVG(col)Average valueSELECT AVG(Salary) FROM EmployeeSalary
🔢

COUNT with Alias

Use AS to give a temporary alias to a column for readability.

SQL
SELECT COUNT(*) AS [Number of Records]
FROM customer
WHERE CustomerFirstName LIKE 'B%';
📅

Aggregate by Month

Use the MONTH() function to extract the month from a date column and group by it.

SQL
SELECT
  MONTH(SaleDate) AS [Month],
  COUNT(*) AS [Number of Sales],
  SUM(SaleQuantity * SaleUnitPrice) AS [Total Amount]
FROM sale
GROUP BY MONTH(SaleDate);
📊 Lesson 05

GROUP BY & HAVING

GROUP BY organizes rows into groups for aggregation. HAVING filters groups after aggregation — it's like WHERE but for aggregate results.

📦

SUM with GROUP BY

Group sales by employee and calculate totals for each.

SQL
SELECT
  sale.EmployeeID,
  EmployeeFirstName,
  EmployeeLastName,
  COUNT(*) AS [Number of Orders],
  SUM(SaleQuantity) AS [Total Quantity]
FROM sale, employee
WHERE sale.EmployeeID = employee.EmployeeID
GROUP BY sale.EmployeeID, EmployeeFirstName, EmployeeLastName;
🔒

HAVING — Filter After Grouping

WHERE filters rows before grouping. HAVING filters groups after aggregation.

SQL
-- Only show job titles with more than 1 employee
SELECT JobTitle, COUNT(JobTitle)
FROM EmployeeDemographics ED
JOIN EmployeeSalary ES ON ED.EmployeeID = ES.EmployeeID
GROUP BY JobTitle
HAVING COUNT(JobTitle) > 1;

-- Only show job titles with average salary above 45k
SELECT JobTitle, AVG(Salary)
FROM EmployeeDemographics ED
JOIN EmployeeSalary ES ON ED.EmployeeID = ES.EmployeeID
GROUP BY JobTitle
HAVING AVG(Salary) > 45000
ORDER BY AVG(Salary);
⚠️ You cannot use WHERE with aggregate functions. Use HAVING instead.
🔗 Lesson 06

SQL Joins

Joins combine rows from two or more tables based on a related column. They are the core mechanism for working with relational data.

Join TypeReturns
INNER JOINOnly matching rows from both tables
LEFT JOINAll rows from left + matching from right (NULLs where no match)
RIGHT JOINAll rows from right + matching from left
FULL OUTER JOINAll rows from both tables (NULLs where no match)
CROSS JOINEvery combination of rows (Cartesian product)
SELF JOINA table joined with itself (for hierarchies)
🤝

INNER JOIN

Returns only the rows where a match exists in both tables.

SQL
-- Explicit join syntax
SELECT
  InventoryName, SaleDate, SaleUnitPrice,
  SaleQuantity, SaleUnitPrice * SaleQuantity AS [Total Amount]
FROM inventory
INNER JOIN sale ON sale.InventoryID = inventory.InventoryID
ORDER BY InventoryName;

-- Implicit join (older syntax, same result)
SELECT * FROM inventory, sale
WHERE sale.InventoryID = inventory.InventoryID;
⬅️

LEFT JOIN & RIGHT JOIN

LEFT JOIN keeps all rows from the left table. RIGHT JOIN keeps all from the right.

SQL
-- LEFT JOIN: show all inventory, even those with no sales
SELECT inventory.InventoryID, InventoryName
FROM inventory
LEFT JOIN sale ON sale.InventoryID = inventory.InventoryID;

-- Find inventory items with NO sales
SELECT inventory.InventoryID, InventoryName
FROM inventory
LEFT JOIN sale ON sale.InventoryID = inventory.InventoryID
WHERE sale.InventoryID IS NULL;

-- Same result using a subquery (no join needed)
SELECT InventoryID, InventoryName FROM inventory
WHERE InventoryID NOT IN (SELECT InventoryID FROM sale);
🔄

SELF JOIN — Hierarchies

Join a table to itself — commonly used to process hierarchy data like employee/manager relationships.

EmployeeIDNameManagerID
1001Tan Mei LingNULL
1002Kelvin Koh1001
1003Amin Wong1002
SQL
-- INNER JOIN: only employees who HAVE a manager
SELECT
  E.EmployeeID,
  E.EmployeeFirstName + ' ' + E.EmployeeLastName AS [Full Name],
  E.ManagerID,
  M.EmployeeFirstName + ' ' + M.EmployeeLastName AS [Manager Name]
FROM staff E
INNER JOIN staff M ON E.ManagerID = M.EmployeeID;

-- LEFT OUTER JOIN: show ALL employees (including the top boss)
SELECT
  E.EmployeeID,
  E.EmployeeFirstName + ' ' + E.EmployeeLastName AS [Full Name],
  E.ManagerID,
  M.EmployeeFirstName + ' ' + M.EmployeeLastName AS [Manager Name]
FROM staff E
LEFT OUTER JOIN staff M ON E.ManagerID = M.EmployeeID;
✖️

CROSS JOIN & FULL OUTER JOIN

CROSS JOIN produces every combination of rows (Cartesian product). FULL OUTER JOIN returns all rows from both tables.

SQL
-- CROSS JOIN: all combinations
SELECT * FROM inventory1
CROSS JOIN inventory2;

-- FULL OUTER JOIN: everything from both tables
SELECT sale.InventoryID, InventoryName
FROM inventory
FULL OUTER JOIN sale ON sale.InventoryID = inventory.InventoryID
WHERE sale.InventoryID IS NULL;
🔀 Lesson 07

Unions & Set Operations

Set operations combine the results of two queries. Unlike joins, they stack rows vertically. Both queries must have the same number of columns with matching data types.

OperationDuplicates?Description
UNIONRemovedCombine & deduplicate
UNION ALLKeptCombine everything
INTERSECTRemovedOnly rows in both queries
EXCEPTRemovedOnly rows in the first query
🔗

UNION vs UNION ALL

SQL
-- UNION: merge and remove duplicates
SELECT cust_lname, cust_fname FROM customer
UNION
SELECT cust_lname, cust_fname FROM customer_2;

-- UNION ALL: merge and keep all rows, including duplicates
SELECT cust_lname, cust_fname FROM customer
UNION ALL
SELECT cust_lname, cust_fname FROM customer_2;
🎯

INTERSECT & EXCEPT

SQL
-- INTERSECT: only rows common to both tables
SELECT cust_lname, cust_fname FROM customer
INTERSECT
SELECT cust_lname, cust_fname FROM customer_2;

-- EXCEPT: rows in customer that are NOT in customer_2
SELECT cust_lname, cust_fname FROM customer
EXCEPT
SELECT cust_lname, cust_fname FROM customer_2;
🔀 Lesson 08

CASE Statements & Type Casting

CASE adds conditional (if-else) logic directly into your queries. CAST and CONVERT let you change data types on-the-fly.

🔄

CAST & CONVERT

Temporarily change data types for a query.

SQL
-- CAST(expression AS datatype)
SELECT CAST('2017-08-25 00:00:00.000' AS date);

-- CONVERT(data_type, expression, style)
SELECT CONVERT(date, '2017-08-25 00:00:00.000');
🔀

CASE WHEN ... THEN ... END

Apply conditional logic — categorize data or compute new values based on conditions.

SQL
-- Categorize by age
SELECT FirstName, LastName, Age,
  CASE
    WHEN Age > 30 THEN 'Old'
    WHEN Age BETWEEN 27 AND 30 THEN 'Young'
    ELSE 'Baby'
  END AS AgeCategory
FROM EmployeeDemographics
WHERE Age IS NOT NULL
ORDER BY Age;

-- Calculate salary raises by job title
SELECT FirstName, LastName, JobTitle, Salary,
  CASE
    WHEN JobTitle = 'Salesman'   THEN Salary + (Salary * 0.10)
    WHEN JobTitle = 'Accountant' THEN Salary + (Salary * 0.05)
    WHEN JobTitle = 'HR'         THEN Salary + (Salary * 0.000001)
    ELSE Salary + (Salary * 0.03)
  END AS SalaryAfterRaise
FROM EmployeeDemographics ED
JOIN EmployeeSalary ES ON ED.EmployeeID = ES.EmployeeID;
🧩 Lesson 09

Subqueries

A subquery is a query nested inside another query. They can appear in the SELECT, FROM, or WHERE clause — each with a different use case.

📌

Subquery in SELECT

Embed a query inside a column expression to compute a value alongside each row.

SQL
-- Show each employee's salary alongside the overall average
SELECT EmployeeID, Salary,
  (SELECT AVG(Salary) FROM EmployeeSalary) AS AllAvgSalary
FROM EmployeeSalary;

-- Equivalent using window function
SELECT EmployeeID, Salary,
  AVG(Salary) OVER () AS AllAvgSalary
FROM EmployeeSalary;
📂

Subquery in FROM & WHERE

SQL
-- Subquery in FROM (derived table)
SELECT a.EmployeeID, AllAvgSalary
FROM (
  SELECT EmployeeID, Salary, AVG(Salary) OVER () AS AllAvgSalary
  FROM EmployeeSalary
) a
ORDER BY a.EmployeeID;

-- Subquery in WHERE: employees over 30
SELECT EmployeeID, JobTitle, Salary
FROM EmployeeSalary
WHERE EmployeeID IN (
  SELECT EmployeeID FROM EmployeeDemographics
  WHERE Age > 30
);

-- Find employees with the highest salary
SELECT EmployeeID, JobTitle, Salary
FROM EmployeeSalary
WHERE Salary IN (SELECT MAX(Salary) FROM EmployeeSalary);
🏅 Lesson 10

Window & Ranking Functions

Window functions compute values across a set of rows related to the current row — without collapsing the result set like GROUP BY does.

FunctionDuplicates Get…Gaps?
ROW_NUMBER()Different ranksNo
RANK()Same rankYes (skips)
DENSE_RANK()Same rankNo (consecutive)
NTILE(n)Distributed into n groupsN/A
1️⃣

ROW_NUMBER()

Assigns a unique sequential number to each row. Even rows with identical values get different numbers.

SQL
SELECT *,
  ROW_NUMBER() OVER (ORDER BY Salary DESC) AS SalaryRank
FROM EmployeeSalary;
🥇

RANK() vs DENSE_RANK()

RANK() skips numbers after ties. DENSE_RANK() keeps them consecutive.

SQL
-- RANK: ties get same rank, then skip (1, 2, 2, 4)
SELECT *,
  RANK() OVER (ORDER BY Salary DESC) AS SalaryRank
FROM EmployeeSalary;

-- DENSE_RANK: ties get same rank, no skip (1, 2, 2, 3)
SELECT *,
  DENSE_RANK() OVER (ORDER BY Salary DESC) AS SalaryRank
FROM EmployeeSalary;

-- With PARTITION BY: rank within each job title group
SELECT *,
  RANK() OVER (PARTITION BY JobTitle ORDER BY Salary DESC) AS SalaryRank
FROM EmployeeSalary
ORDER BY JobTitle, SalaryRank;
📊

NTILE(n) & PARTITION BY

Divide rows into n roughly equal groups. PARTITION BY returns a per-row value without collapsing rows.

SQL
-- Split into 3 salary groups
SELECT *,
  NTILE(3) OVER (ORDER BY Salary DESC) AS SalaryGroup
FROM EmployeeSalary;

-- PARTITION BY: count per gender alongside each row
SELECT FirstName, LastName, Gender, Salary,
  COUNT(Gender) OVER (PARTITION BY Gender) AS TotalGender
FROM EmployeeDemographics ED
JOIN EmployeeSalary ES ON ED.EmployeeID = ES.EmployeeID;

String Functions

SQL provides powerful string manipulation functions for cleaning, transforming, and extracting text data.

FunctionPurpose
TRIM()Remove leading & trailing spaces
LTRIM() / RTRIM()Remove left/right spaces only
REPLACE(str, old, new)Replace occurrences of a substring
SUBSTRING(str, start, len)Extract part of a string
UPPER() / LOWER()Change case
CHARINDEX(sub, str)Find position of a substring
LEN(str)Get string length
PARSENAME(str, piece)Extract dot-separated parts (right to left)
✂️

TRIM, REPLACE & Case

SQL
-- Remove spaces
SELECT EmployeeID, TRIM(EmployeeID) AS IDTRIM FROM EmployeeErrors;
SELECT EmployeeID, LTRIM(EmployeeID) AS IDLTRIM FROM EmployeeErrors;

-- Replace unwanted text
SELECT LastName,
  REPLACE(LastName, '- Fired', '') AS LastNameFixed
FROM EmployeeErrors;

-- Change case
SELECT FirstName, UPPER(FirstName) FROM EmployeeErrors;
SELECT FirstName, LOWER(FirstName) FROM EmployeeErrors;
🔪

Splitting Strings by Delimiter

Split addresses or other delimited data using SUBSTRING + CHARINDEX, or PARSENAME + REPLACE.

SQL
-- Method 1: SUBSTRING + CHARINDEX
SELECT PropertyAddress,
  SUBSTRING(PropertyAddress, 1,
    CHARINDEX(',', PropertyAddress) - 1) AS Address,
  SUBSTRING(PropertyAddress,
    CHARINDEX(',', PropertyAddress) + 1,
    LEN(PropertyAddress)) AS City
FROM NashvilleHousing;

-- Method 2: PARSENAME (works with dots, so replace commas first)
-- Note: PARSENAME numbers right-to-left!
SELECT OwnerAddress,
  PARSENAME(REPLACE(OwnerAddress, ',', '.'), 3) AS Street,
  PARSENAME(REPLACE(OwnerAddress, ',', '.'), 2) AS City,
  PARSENAME(REPLACE(OwnerAddress, ',', '.'), 1) AS State
FROM NashvilleHousing;
💡 PARSENAME is designed for dot-separated object names, but works great as a quick string splitter when combined with REPLACE.
🧹

Fuzzy Matching with SUBSTRING

Join tables on partial string matches to handle messy data.

SQL
SELECT
  SUBSTRING(err.FirstName, 1, 3),
  SUBSTRING(dem.FirstName, 1, 3),
  SUBSTRING(err.LastName, 1, 3),
  SUBSTRING(dem.LastName, 1, 3)
FROM EmployeeErrors err
JOIN EmployeeDemographics dem
  ON SUBSTRING(err.FirstName, 1, 3) = SUBSTRING(dem.FirstName, 1, 3)
  AND SUBSTRING(err.LastName, 1, 3) = SUBSTRING(dem.LastName, 1, 3);

Views, CTEs & Temp Tables

SQL provides multiple ways to create reusable or temporary result sets. Each has different persistence and use cases.

FeaturePersists?Updates with base?Where stored?
VIEWYes✅ YesDatabase
#Temp TableSession❌ NoTempdb
CTEQuery onlyN/AMemory
👁️

CREATE VIEW

A view is a saved query that acts like a virtual table. It always reflects current data.

SQL
CREATE VIEW CustomerView AS
SELECT
  CustomerFirstName + ' ' + CustomerLastName AS [Customer Name],
  CustomerPhoneNumber,
  InventoryName, SaleDate, SaleQuantity, SaleUnitPrice,
  SaleQuantity * SaleUnitPrice AS [Total Amount]
FROM customer
INNER JOIN sale ON customer.CustomerID = sale.CustomerID
INNER JOIN inventory ON sale.InventoryID = inventory.InventoryID;
#️⃣

Temp Tables

Prefixed with #, temp tables live in tempdb and disappear when the session ends. They support all CRUD operations.

SQL
DROP TABLE IF EXISTS #temp_Employee;

CREATE TABLE #temp_Employee (
  JobTitle       varchar(100),
  EmployeesPerJob int,
  AvgAge         int,
  AvgSalary      int
);

INSERT INTO #temp_Employee
SELECT JobTitle, COUNT(JobTitle), AVG(Age), AVG(Salary)
FROM EmployeeDemographics emp
JOIN EmployeeSalary sal ON emp.EmployeeID = sal.EmployeeID
GROUP BY JobTitle;

SELECT * FROM #temp_Employee;
📎

CTE — Common Table Expression

A CTE creates a temporary named result set that exists only for the duration of a single query. Defined with WITH ... AS.

SQL
WITH CTE_Employee AS (
  SELECT FirstName, LastName, Gender, Salary,
    COUNT(Gender) OVER (PARTITION BY Gender) AS TotalGender
  FROM EmployeeDemographics ED
  JOIN EmployeeSalary ES ON ED.EmployeeID = ES.EmployeeID
  WHERE Salary > 45000
)
SELECT FirstName, LastName, Gender, TotalGender
FROM CTE_Employee
WHERE TotalGender = (SELECT MIN(TotalGender) FROM CTE_Employee);
⚠️ CTEs are stored in memory — you cannot create indexes on them. Use temp tables for large datasets that need indexing.
🧹

Remove Duplicate Records

Combine ROW_NUMBER() with a CTE to identify and delete duplicates.

SQL
WITH RowNumCTE AS (
  SELECT *,
    ROW_NUMBER() OVER (
      PARTITION BY ParcelID, PropertyAddress,
                   SalePrice, SaleDate, LegalReference
      ORDER BY UniqueID
    ) AS row_num
  FROM NashvilleHousing
)
-- Step 1: Preview duplicates
SELECT * FROM RowNumCTE WHERE row_num > 1;

-- Step 2: Delete them (uncomment DELETE, comment SELECT)
-- DELETE FROM RowNumCTE WHERE row_num > 1;
⚙️ Lesson 13

Stored Procedures

Stored procedures are precompiled SQL scripts saved on the server. They accept parameters, encapsulate complex logic, and can be reused with a single EXEC call.

⚙️

CREATE PROCEDURE with Parameters

SQL
CREATE PROCEDURE Temp_Employee
  @JobTitle nvarchar(100)
AS
  DROP TABLE IF EXISTS #temp_employee;

  CREATE TABLE #temp_employee (
    JobTitle       varchar(100),
    EmployeesPerJob int,
    AvgAge         int,
    AvgSalary      int
  );

  INSERT INTO #temp_employee
  SELECT JobTitle, COUNT(JobTitle), AVG(Age), AVG(Salary)
  FROM EmployeeDemographics emp
  JOIN EmployeeSalary sal ON emp.EmployeeID = sal.EmployeeID
  WHERE JobTitle = @JobTitle
  GROUP BY JobTitle;

  SELECT * FROM #temp_employee;
GO;
▶️

Execute a Stored Procedure

Once created, call the procedure anytime with different parameter values.

SQL
-- Run the stored procedure with a parameter
EXEC Temp_Employee @JobTitle = 'Salesman';
💡 Stored procedures are precompiled by the database engine, so they execute faster than ad-hoc queries.
🛠️

ISNULL — Handle Missing Data

Fill in missing values by pulling from another record. Great for data cleaning.

SQL
-- Find rows where PropertyAddress is null and fill from matching ParcelID
SELECT
  a.ParcelID, a.PropertyAddress,
  b.ParcelID, b.PropertyAddress,
  ISNULL(a.PropertyAddress, b.PropertyAddress) AS FilledAddress
FROM NashvilleHousing a
JOIN NashvilleHousing b
  ON a.ParcelID = b.ParcelID
  AND a.[UniqueID] <> b.[UniqueID]
WHERE a.PropertyAddress IS NULL;

-- Update the records
UPDATE a
SET PropertyAddress = ISNULL(a.PropertyAddress, b.PropertyAddress)
FROM NashvilleHousing a
JOIN NashvilleHousing b
  ON a.ParcelID = b.ParcelID
  AND a.[UniqueID] <> b.[UniqueID]
WHERE a.PropertyAddress IS NULL;
